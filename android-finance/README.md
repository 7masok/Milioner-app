# Финансы 0.1.11 · Android

Исправлен повтор Kaspi-переводов на границах страниц PDF: банковский footer и номер/дата справки удаляются из новых названий и ключей. APK очищает ответ действующего backend до предпросмотра. Старые операции сопоставляются только при доказанном следе этого footer, точном совпадении счёта, даты/времени, направления, валюты, суммы и очищенного описания. Сопоставление сохраняет количество одинаковых платежей; части распределённой операции рассматриваются вместе. При отправке повторного импорта используются прежние банковские идентификаторы — сервер тоже пропускает повтор без изменения баланса. Рабочие записи и уже созданные дубли автоматически не меняются. В 0.1.1 — versionCode 2; исправление сохранено в последующих версиях.

В 0.1.2 (versionCode 3) журнал поддерживает «Свой период» с двумя включёнными календарными датами. Счёт, категория и тип комбинируются; даты и фильтры сохраняются после перезапуска. При наличии банковской даты фильтр использует дату операции, а не дату импорта. «Скачать выписку» сохраняет таблицу CSV (UTF-8 с BOM) или документ HTML системным диалогом Android. Выгрузка содержит ровно выбранные операции, заголовки фильтров и поступления/списания отдельно по валютам. Перевод на выбранный счёт использует сумму и валюту зачисления; возвраты и транзит остаются в журнале. Эти итоги — суммы движений, включая транзит и переводы, а не аналитические доходы/расходы или расчёт начального/конечного баланса. Выгрузка читает текущую загруженную локальную историю и не пишет финансовые данные. CSV обезвреживает формулы в текстовых полях, HTML экранирует пользовательский текст и не содержит скриптов. Новый APK подписан прежним ключом, устанавливается поверх 0.1.0/0.1.1.

Package `kz.luxar.finance`, Android 8+. Самостоятельная иконка, встроенный финансовый интерфейс, отдельные сессия и IndexedDB. Вход существующим кодом склада; финансовый PostgreSQL backend остаётся общим. В APK нет пользовательского бэкапа или кода доступа. Удаление приложения очищает локальную очередь; перед этим нужно дождаться синхронизации.

PDF выбирается системным диалогом или передаётся через Android «Поделиться». Сначала показывается предпросмотр; подтверждение импорта остаётся пользовательским. Резервная копия JSON сохраняется через системный диалог без разрешения на весь накопитель. Веб-ресурсы APK обслуживаются только по точному списку HTTPS-путей. Сетевые запросы разрешены только существующему backend. Сертификаты HTTPS проверяются WebView.

Сборка: Android platform 35, Build Tools 35.0.0, Java 17 и ECJ 3.38.0. Указать `FINANCE_ANDROID_SDK` (папка с android-35/android.jar и Build Tools), `FINANCE_ECJ_JAR`, `FINANCE_SIGNING_KEY` (локальный тестовый ключ, не коммитить); затем `python3 android-finance/build.py`. APK для прямой установки подписывается тестовым ключом. Для обновлений сохранять тот же ключ. Публикация в Google Play не выполнялась.

Сборка, подпись и состав APK проверены автоматически; установка на физический Android-телефон ещё не проверена.

В 0.1.3 (versionCode 4) формат по умолчанию — настоящий `.xlsx`. HTML удалён из списка форматов, CSV остаётся запасным. Excel создаётся полностью на устройстве из встроенного шаблона оформления (artifact-tool), без сервера и внешних библиотек в APK. Даты и суммы числовые, строки заголовков закреплены, автофильтр включён, колонки широкие, текстовые поля переносятся по словам. Пустые дополнительные колонки не экспортируются. Движения перевода показаны по каждому выбранному счёту; итоги по валютам вычисляются SUMIFS и пересчитываются в Excel. Число операций в шапке — число исходных записей журнала, поэтому при всех счетах один перевод может дать две строки движений. Все пользовательские тексты записаны как literal inline strings, не формулы. Даты и суммы проверены независимым XLSX-reader; импорт и перерасчёт итогов — artifact-tool. Нативный адаптер принимает только CSV или XLSX MIME, Excel передаётся base64 и сохраняется как исходные байты через ACTION_CREATE_DOCUMENT; backup JSON сохраняет свою проверку формата.

В 0.1.4 (versionCode 5) исправлено обрезание Excel в WebView prompt IPC: XLSX, CSV и JSON передаются base64-частями по 4000 символов с идентификатором, порядковым номером, ожидаемой длиной и проверкой завершения. Диалог сохранения открывается только после получения полного файла; незавершённая передача отменяется. Общий предел — 16 млн символов base64. Ошибки JSON-парсера больше не выводят содержимое файла на экран. Проверки включают передачу большого XLSX при искусственном ограничении prompt до 10 КБ, Unicode CSV/backup, прерывание передачи, нативную проверку порядка/длины/формата и повторную сборку с прежней подписью.

В 0.1.5 (versionCode 6) `finance-bcc-identity.js` сопоставляет BCC-покупки после уточнения названия по счёту/IBAN, календарной дате, точному времени до секунды, направлению и исходной сумме/валюте. Оценка суммы в тенге и текст продавца не входят в новый ключ для таких строк. Старые импорты сопоставляются без изменения их ID/категорий/балансов; повторная отправка использует прежние ключи, поэтому действующий backend тоже пропускает повтор. Каждая историческая операция используется один раз; части платежа рассматриваются одной полной суммой. Если точного времени нет, изменение названия не служит основанием автоматически скрывать новую операцию. BCC posted-строка без времени может сопоставиться с единственной blocked-строкой по неизменному продавцу и исходной сумме. Kaspi-проверки и aliases перевода сохранены.

Отступы строки состояния/навигации и выреза применяются к нативному FrameLayout вокруг WebView. Сам WebView занимает внутреннюю область, поэтому его заголовок и HTML-окна не пересекаются с системной строкой на Android 15/16 с обязательным edge-to-edge. Системные значки тёмные на белом фоне. Сборка/подпись и проверки модели/настоящего предпросмотра пройдены; отступы на физическом телефоне требуют проверки после обновления.

В 0.1.6 (versionCode 7) исправлен возможный вылет в `onCreate` версии 0.1.5: системный WindowInsetsController может быть null до готовности окна. `NativeChrome.install` не обращается к нему при запуске; настройка значков происходит через прикреплённый View.post и при получении отступов, с явной проверкой null. Отступы по-прежнему применяются к нативному контейнеру. `FINANCE_ECJ_JAR=... python3 android-finance/test-native-chrome.py` исполняет настоящий NativeChrome на фикстурах API 26/29/30/35/36: прежний NPE воспроизводится, новая инициализация проходит при отсутствующем/позднем контроллере и повторных отступах. Это проверка Java-жизненного цикла с API-фикстурами, а не запуск APK на физическом телефоне. Исправления BCC и Excel сохранены.

В 0.1.7 (versionCode 8) формы дохода/расхода/транзита и межсчётного перевода содержат календарную дату. По умолчанию — сегодня; при редактировании — дата сохранённой операции. При создании доступно «Не менять текущий баланс»: запись сохраняется с `affectsBalance:false`, поэтому ни создание, ни последующее изменение/удаление такой записи не меняют остатки. Доход/расход остаётся в категориях и аналитике за выбранную дату; перевод/транзит сохраняют прежние правила исключения из доходов/расходов. В журнале и выписке виден режим без влияния на баланс. При редактировании режим баланса сохраняется и не переключается: это предотвращает обратное начисление старого списания.

Дата операции имеет приоритет над timestamp создания/импорта при фильтрации и аналитике. `createdAt` сохраняет своё прежнее назначение и не переписывается при редактировании. Пустые/несуществующие даты блокируют сохранение. Если дата изменена перед разбивкой, её сначала нужно сохранить; во время распределения дата недоступна. Проверки: настоящие формы/сохранения local ledger, отправляемый JSON и существующий server-effects код, прошлая дата в категории/CSV, редактирование/удаление history-only записи, обычные операции/переводы, ошибки даты, полный npm test и DOM со всеми подключёнными скриптами. Backend уже принимает `affectsBalance:false`, его deploy/миграции не нужны.

В 0.1.8 (versionCode 9) исправлена неактивная кнопка разделения платежа в предпросмотре PDF. Generated core хранит financeStatementDraft в глобальном `let`, который не является свойством window. Модуль импорта теперь читает ту же лексическую переменную во всех этапах: открытие/категории, сумма, разворачивание частей при импорте и восстановление после ошибки. Если предпросмотр уже закрыт, выводится пояснение вместо молчаливого выхода. Проверки исполняют настоящий core с отсутствующим window.financeStatementDraft: открытие/отмена, точная сумма частей и транзит, сохранение исходных банковских ключей, повторный импорт, ошибка хранения и повтор. Полный DOM со всеми shipped-скриптами дополнительно проверяет реальные inline-нажатия кнопок до импорта 59300 как 20000/30000/9300. Остальные изменения, native startup и подпись сохранены.

В 0.1.9 (versionCode 10) в поступлении «Возврат» появился ручной выбор исходного расхода с поиском по названию/категории/дате. Частичный возврат не требует равенства сумм или совпадения продавца; можно выбрать расход из сохранённой истории или этой же выписки, включая конкретную часть ещё не импортированного разделённого платежа. Допускается другой счёт в той же валюте. Старое ограничение 60 дней и 8 результатов снято для ручного списка. Транзит, переводы, будущие расходы и другая валюта не предлагаются. Предыдущие возвраты и выбранные новые возвраты резервируют доступную сумму; перед local-first импортом она проверяется заново. Уже импортированные повторные строки не резервируют сумму второй раз.

Возврат сохраняет существующие refundOfId/refundCategory поля, пополняет счёт как банковское поступление и уменьшает расход категории вместо дохода; сумма исходной покупки сохраняется. Пример фикстуры: 59300 покупки, 10500 возврата, 48800 чистого расхода. Временные ссылки на части выписки переводятся в ID соответствующих строк batch; ошибка хранения возвращает прежние ссылки/предпросмотр для повтора. Действующий backend уже поддерживает поля возврата; новый deploy не нужен. Проверки: finance-partial-refunds.test.mjs, split/runtime/transfer и полный npm test, DOM со всеми статическими скриптами и настоящими inline-событиями, сборка и подпись APK. Проверки лимита выполняются по актуальной загруженной истории и текущему предпросмотру.

В 0.1.10 (versionCode 11) выбор исходного платежа для возврата заменён компактным списком прямо в предпросмотре, без системного Android-меню. Сверху остаётся поиск по сумме (59300, 59 300, 59300,00), названию, категории или дате. Сначала показаны выбранные покупки «Из этой выписки», затем «Уже импортированные»; сумма, описание и дата/категория представлены отдельными строками. Поиск учитывает исходную и оставшуюся невозвращённую сумму. Части разбивки выбираются отдельно.

Покупки текущей выписки видны и до назначения категории. Их можно связать с поступлением в том же импорте, даже если поступление расположено раньше покупки; перед сохранением категория обязательна. Список обновляется при изменении категории, чекбокса, перевода или частей. Проверки: поиск с пробелами/десятичными знаками, ручные inline-нажатия нового списка в полном DOM, покупка+возврат до первого импорта, разделение 50000 на 10000/20000/20000 с возвратом 15000 к последней части и чистым расходом 35000, прежние лимиты/повторы/восстановление при ошибке, полный npm test и сборка с прежней подписью. Backend и данные пользователя не изменяются.

В 0.1.11 (versionCode 12) предпросмотр PDF показывает все операции по календарной дате от новых к старым, внутри дня — по времени. Проведённые и заблокированные BCC-платежи находятся в одном хронологическом списке. Одинаковые дата/время сохраняют исходный взаимный порядок; неизвестная дата помещается в конец, отсутствующее время не выдумывается. Сортируется только представление: исходные строки, индексы, банковские ключи, ссылки возвратов и разбивок сохраняются. Проверки: реальный core-предпросмотр со смешанными статусами/датами/временем, неизменность исходных строк, полный DOM с настоящими обработчиками разбивки/возврата, полный npm test и APK с прежней подписью. Backend и пользовательские данные не изменяются.
