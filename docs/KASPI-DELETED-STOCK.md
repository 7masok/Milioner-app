# Удаление складского товара и остаток Kaspi · 29.10.2026

При удалении товара или снятии его Kaspi-привязки известный складской SKU больше не наследует старый положительный остаток из kaspi_price_template. PostgreSQL хранит точные seller SKU, которыми управлял склад; триггер warehouse_products запоминает основную привязку и kaspiAliases до и после изменения, включая физическое удаление. Миграция запоминает текущие привязки, а для одного сообщённого владельцем ранее удалённого товара добавляет проверенный SKU.

Генератор публичной автоматической выгрузки оставляет такую позицию с stockCount=0 и available=no. Действующая точная привязка склада приоритетна: повторное связывание возвращает актуальный свободный остаток. Чужие XML-only позиции, которыми склад не управлял, не обнуляются. Цены и фактический складской остаток не меняются. Полного восстановления ранее удалённых неизвестных SKU не выполняется: их нельзя определять по похожему названию.

Ручная загрузка файла не нужна, если у Kaspi уже настроена автоматическая ссылка на этот feed. Изменения поступят после следующего чтения Kaspi; приложение не выдаёт это за немедленное подтверждение площадкой. Для срочного снятия/обнуления используется кабинет Kaspi. Показанное количество в «Сняты с продажи» само по себе не подтверждает доступность предложения покупателям.

Проверки: kaspi-stock-feed.test.mjs — исчезнувшая привязка, нулевой/положительный действующий остаток, сохранность сторонних XML-позиций, история основной привязки и алиасов. Перед выпуском полный npm test. После выпуска отдельно проверяется фактический XML по точному SKU.
