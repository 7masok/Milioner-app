# Остаток после движения и найденный товар

31.10.2026. В обычной карточке товара / конкретного размера — «＋ Добавить остаток». Это прибавление найденных единиц, а не полный пересчёт: было 10, добавлено 3, стало 13. Инвентаризация по-прежнему задаёт весь фактический остаток. Составные наборы отдельно не пополняются.

Ввод: целое положительное количество и себестоимость найденной штуки (по умолчанию текущая стоимость). Предпросмотр показывает арифметику. Записывается движение «излишек» с положительной дельтой, новая отдельная FIFO-партия с inventoryAdjustment/foundStock; она не считается закупкой у поставщика. Стоимость прежних партий не меняется. Для старого нераспределённого по FIFO остатка создаётся исходная партия по прежней стоимости. Резервы и блокировки неподтверждённых WB-размеров сохраняются. Запись идёт по прежнему протоколу сохранения и ревизий, проверка stockLedgerViolation действует.

Новые движения содержат stockBalance: физический учётный остаток после проводки, включая резерв. Это остаток в продаже product.stock, а не товар в пути или непринятая складская партия. Складское списание отдельно фиксирует остаток at_warehouse. В списке под количеством показано «Осталось N шт.» / «На складе N шт.». Переход с положительного количества на ноль выделен «Закончился», без создания искусственной нулевой операции.

Зафиксированы ручные операции через оба log-renderer, серверные продажи/восстановления, исправление состава Kaspi и отправка FBO. Наблюдение включает подпись productId/type/date/qty/scope; при несоответствии оно не отображается. Изменение исторической инвентаризации сбрасывает наблюдения этого товара начиная с изменённой даты, чтобы не выдавать старые числа за пересчитанную историю. Более старые записи без наблюдений показывают «Остаток не записан». Для старых инвентаризаций с явным «было N, стало M» значение доступно при точном соответствии дельты. Обратный пересчёт от сегодняшнего остатка по потенциально неполной истории не используется.

Изменения payload сохраняются в существующей warehouse_movements, без новых таблиц, массового восстановления истории или изменения рабочих остатков при обновлении. Проверки: movement-stock-balance.test.mjs, stock-adjustments.test.mjs, warehouse-ledger.test.mjs, marketplace-sale-reconcile / Kaspi content / FBO checks и полный npm test.
