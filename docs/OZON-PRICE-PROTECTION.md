# Защита цен Ozon · 29.10.2026

Дополнение к PRICE-06/PRICE-07 паспорта. Защита включается явно для одного товара или показанного списка во вкладке «Цены → Ozon». Перед массовым включением пользователь видит отдельную фиксированную цену и валюту каждого товара. Кабинеты разделены; настройки, очередь и результаты хранятся в PostgreSQL. По умолчанию все товары без защиты. Включение не запускает автоматическую защиту остальных товаров.

Цена защиты — целевая цена продавца. Сервер передаёт её как price и min_price, old_price=0, отключает auto_action_enabled и price_strategy_enabled, включает min_price_for_auto_actions_enabled. Цены не вычисляются от предыдущей акционной цены и не повышаются автоматически вслед за лимитом акции. Обычный редактор не может спорить с включённой защитой: цену меняют в настройке защиты либо сначала отключают её. Все изменения одного кабинета сериализуются advisory lock. Перед записями цикл повторно проверяет offer_id + product_id и валюту через актуальный API цен; переиспользованный артикул или смена валюты блокируют дальнейшие записи для товара.

После 19.10.2026 устаревшие v1 actions/products/deactivate, actions/products и auto-add/products/delete не используются. Цикл получает GET /v1/actions, страницы /v2/actions/products с last_id, отдельные волны /v2/actions/auto-add/products/list с точной датой из auto_add_dates и offset. Запланированное участие удаляется /v2/actions/auto-add/products/delete. Промокоды исключаются /v2/actions/products/deactivate. Если этот способ не поддерживается, для нового /v1/actions/products/update используется только заранее подтверждённая фиксированная цена, строго выше известного max_action_price в той же валюте. Неизвестный порог либо недостаточная цена дают предупреждение, без самостоятельного повышения. Ответ требует подтверждения конкретного product_id, без active_product_ids, rejected и warnings.

После действий сервер повторно получает список акций, текущий состав, будущие волны и итоговые цены. «Проверено» означает отсутствие товара в просмотренных акциях и будущих волнах, совпадение подтверждённой цены продавца и минимальной цены с настройкой (минимальная не ниже цели). Это результат на указанное время, не обещание отсутствия новых акций между проверками. Неизвестные даты, неполный состав, ошибка доступа, оставшееся участие и скидка продавца дают «Нужно внимание» или «Ошибка проверки». marketing_price за счёт Ozon не подменяет marketing_seller_price. Отображается дата проверки по Алматы; результат старше 30 минут помечается как ожидающий свежей проверки.

Фоновый процесс работает при закрытом браузере: один внешний запрос на кабинет за шаг с интервалом не менее 5 секунд, следующий полный проход через 15 минут после окончания предыдущего. Очередь и Retry-After сохраняются после каждого шага и переживают рестарт. Ошибки не превращаются в успешную проверку, неполученное подтверждение безопасно повторяется с той же ценой. При writes-disabled внешние записи не выполняются. Отключение останавливает дальнейший автоконтроль, не добавляет товары обратно в акции и не восстанавливает ранее отключённые стратегии автоматически.

Сопоставление только точное account + offer_id + product_id из серверного снимка цен (не по имени или SKU витрины). Валюта проверяется по этому снимку. Секреты остаются на сервере. Настройки требуют сессии владельца, доверенного origin и confirm=true. Само открытие страницы/карточки защиту не включает и не делает запросов к акциям.

Проверки: ozon-price-protection.test.mjs — полный модельный цикл с повторной проверкой, фиксированная цена, Money/валюта, отказ от автоматического повышения, неполные ответы, несколько страниц и волны, перезапуск, 429, конкурентный lock, точная привязка, owner/origin/confirm, отсутствие записей при загрузке UI. Полный npm test обязателен. Проверка на реальном API с защищёнными товарами не выполнялась: защита остаётся выключенной до выбора владельцем.

Ни это приложение, ни API-настройка минимальной цены не гарантируют абсолютный запрет любых скидок Ozon: у площадки есть отдельные механики и исключения. Поэтому проверяется фактическое участие, а неподтверждённое исключение явно показывается.
