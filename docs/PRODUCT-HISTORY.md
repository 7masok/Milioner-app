# История карточек товаров

В Товарах — «История изменений», внутри карточки — «История товара».
Пользователь видит только создание, удаление и редактирование карточек товаров:
дату по Алматы, название, действие и прежнее/новое значение изменённых полей.
При создании и удалении достаточно события и названия, без полного дампа карточки.
Технических сведений, внутренних ID, ревизий, JSON, служебного источника в интерфейсе нет.
Поиск по названию и фильтр по действию; отдельный выбор типа записи не нужен.

Резервы, партии/закупки, движения, продажи и возвраты не выводятся в этом журнале.
У них остаются существующие разделы и учёт. Сервер ограничивает выборку карточками
до пагинации; фильтр клиента дополнительно защищает от старого/неожиданного ответа.
Ранее сохранённые внутренние события не удаляются и не меняют складские данные.

Журнал хранится независимо от карточки: удалённый товар остаётся в истории.
Подробные события до включения журнала не восстанавливаются. Исходные снимки
baseline не показываются. Фоновые метки синхронизации и наблюдения остатков WB
не создают событий; уже накопленный служебный шум отфильтрован до пагинации.
В этом журнале остаются изменения описания и настроек карточки: название, фото, категория, артикулы, состав и прочие параметры. Изменения учётного остатка (`stock`), себестоимости (`cost`) и накопленной прибыли (`totalProfit`) не выводятся: они относятся к складскому/финансовому учёту. Эта проекция применяется к старым и новым событиям до пагинации; пустая после фильтрации правка не создаёт видимой строки. Если одновременно изменились название и остаток, показывается только название. Создание и удаление карточки остаются.
Общий код входа не определяет конкретного человека, имена авторов не выдумываются.

API только для чтения, с проверкой сессии и origin; 50 событий на страницу с курсором.
Триггеры работают в транзакции: откат не создаёт историю, сохранение без изменений
не создаёт событие. Крупные значения суммируются, секретные ключи исключаются.

Проверки: реальные PostgreSQL-триггеры в PGlite, удаление одного из одноимённых товаров,
откат, повторное сохранение, игнорирование фоновых проверок, серверная фильтрация
типов до пагинации, авторизация, экранирование текста и запоздалые ответы интерфейса.
