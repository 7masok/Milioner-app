# Чередование кампаний по дням

01.11.2026. В группе рекламы — «Тест по дням» с одной кнопкой «Запустить тест». По умолчанию старт сейчас, доступны завтра в 00:00 Алматы и выбранная дата. Порядок 2–3 кампаний и длительность (21 день по умолчанию) спрятаны в дополнительные настройки. Отдельных кнопок сохранения и предпросмотра в UI нет. Ранее сохранённые черновики сами не включаются; установка обновления также ничего не запускает.

Явное нажатие запуска атомарно сохраняет активный план и готовит правила только выбранных кампаний: снимает прежнюю ручную блокировку запуска и выключает индивидуальное расписание. Защита остатков, существующие дневные лимиты и отметка достигнутого лимита сохраняются. Новый лимит и бюджет не придумываются: при отсутствии дневного лимита действует существующий бюджет WB, без пополнения. Старый API режима start без autoPrepare сохраняет прежние строгие требования. Проверяются магазин, членство, один общий единственный nmId, допустимые статусы и версия плана. Все внешние действия идут только после commit.

Исполнитель сразу начинает подготовку: при будущем старте ставит все кампании на паузу и ждёт заданного времени; при старте сейчас оставляет/запускает первую после подтверждения пауз остальных. Нужные свежие данные, остаток и лимит проверяются перед каждым стартом; при временной проблеме план остаётся включённым и повторяет проверку автоматически. Независимый минутный цикл не зависит от успеха загрузки статистики. Ограничения WB и persisted retryAt соблюдаются; статус в открытой форме обновляется каждые 15 секунд. Сутки — 24 часа от времени начала, дата следующего слота не сдвигается из-за ошибок. Бюджет и ставки WB не меняются.

Сначала исполнитель читает статусы WB, ставит другие кампании плана на паузу, затем повторно проверяет их. Запуск следующей разрешён только после подтверждения пауз, повторной проверки запаса/лимита/ручной блокировки. После запуска читается статус WB. Неожиданная пауза текущей кампании не отменяется повторным запуском в этот день. Ручное действие паузы/завершения в приложении переводит весь тест в остановку; ручной запуск во время теста требует сначала остановить тест. Отдельные лимитеры сохраняют право остановки, но не запускают участников действующего теста по старым правилам.

Остановка или окончание срока ставит все активные кампании плана на паузу и ждёт подтверждения. После подтверждения для них сохраняется запрет автоматического запуска, чтобы старый бюджетный лимитер не возобновил завершённый эксперимент. Снять его можно явным ручным возобновлением. До подтверждения остановки возможен расход. Завершённые кампании WB не воскрешаются. Бюджеты/ставки не увеличиваются и не пополняются.

Migration 155 добавляет отдельную таблицу плана, версии, состояния, срока следующей попытки и истории последних 200 переходов. Блокировка строки группы и эксперимента сериализует работников и правки, SKIP LOCKED исключает параллельное исполнение в нескольких экземплярах; активные/останавливающиеся группы нельзя изменить или расформировать. Планы кабинетов изолированы. Прежняя история рекламы и складские данные не переписываются. История переходов видна в форме. Неоднозначные ответы WB показываются как ошибка, а не как подтверждённый запуск.

Сравнение группы по выбранному периоду остаётся отчётным: это не автоматически выделенная статистика только фактических часов теста и не статистически доказанный победитель. Результаты атрибуции кампаний могут пересекаться. На время теста разумно сохранять цену, карточку и ставки стабильными; сам исполнитель эти параметры не меняет.

Официальная спецификация получена 31.10.2026: https://dev.wildberries.ru/api/swagger/yaml/ru/08-promotion.yaml?region=ru. Используются GET /api/advert/v2/adverts?ids=..., /adv/v0/pause и /adv/v0/start через существующую очередь WB. Нет автоматического пополнения бюджета.

Проверки: wb-ad-experiments.test.mjs (календарные границы, 21-дневная ротация, подтверждение пауз, блокировки, ручная пауза, 429/restart, версия и реальный SQL), wb-ad-groups, wb-ads-reliability и полный npm test. Визуальная проверка на телефоне остаётся необходимой: браузерный движок локального окружения не удалось загрузить. Рабочие аккаунты не использовались в проверках.


## Исправление базовых лимитов WB · 02.11.2026

Наблюдавшаяся причина незапуска Нож777: исполнитель трижды читал /api/advert/v2/adverts для одного переключения и конкурировал с обновлением рекламы, хотя базовый токен допускает один запрос этого метода в час. Последующий cooldown делал тест неисполняемым. Теперь проверка статусов использует отдельный /adv/v1/promotion/count: один сохранённый ответ на кабинет/токен не чаще 15 минут с небольшим запасом. Подробный состав кампаний читается не чаще часа; запуск и пауза — не чаще 12 минут для каждого метода. Слоты и 429 Retry-After/X-RateLimit-Retry хранятся в PostgreSQL (migration 156), ключ токена — SHA-256. Повторный запуск процесса не сбрасывает ограничения. Сторонние вызовы продавца также могут занять лимит: ответ WB всегда имеет приоритет.

Переключение — сохраняемый процесс: отправленная пауза ожидает нового наблюдения; только подтверждённая пауза остальных позволяет отправить запуск. Команда запуска и подтверждённая работа различаются. Старое наблюдение до команды либо до границы дня не служит подтверждением; повторные минутные проверки используют кэш и не дублируют команды. Неожиданная пауза подтверждённо работавшей кампании по-прежнему не отменяется. Старый backoff неисполненного теста от подробного метода не переносится на независимый новый метод статусов; отправленные команды и актуальные backoff сохраняются. Включённый план и его даты не переписываются. В форме и на карточке выбранной кампании видны этап, причина и следующая проверка.

Для теста без локального дневного лимита задержка статистики больше не блокирует запуск: точный состав проверяется по часовому снимку (максимум 70 минут), статусы — отдельно, остаток — по актуальному складу. Для включённого локального лимита прежние строгие проверки свежей дневной статистики остаются. Бюджеты и ставки не меняются. При базовом API возможны задержки подтверждения до следующего 15-минутного слота, а при паузе нескольких активных кампаний — несколько слотов. Это явно отображается, не выдаётся за мгновенное переключение.

Проверки: реальные SQL-слоты и кэш, сохранение лимитов после рестарта, интервалы/Retry-After, отложенное подтверждение старта, исключение повторного запуска, подтверждение пауз перед сменой, граница дня, старый backoff, штатные складские/бюджетные блокировки и полный npm test. Официальная спецификация: dev.wildberries.ru/api/swagger/yaml/ru/08-promotion.yaml (лимиты базового токена для перечисленных методов).
