# Накопительная статистика запросов WB

30.10.2026. В карточке кампании WB 1 / WB 2 кнопка «Запросы · корзины». С 01.11.2026 она расположена сразу под заголовком, вне сворачиваемого содержимого, и видна даже у свёрнутой кампании. В группе сначала нужно раскрыть саму группу. Настройки отдельно по кампании: основа показы/клики, минимальное число (по умолчанию 100), минимальный процент корзин (1%), автоматическое исключение (по умолчанию выключено). С 01.11.2026 список сам регистрирует сбор при открытии через отдельный авторизованный POST /collect, без изменения порогов и автоисключения. GET остаётся чтением PostgreSQL. Сохранение настроек оценки независимо от загрузки списка. Новые кампании по умолчанию не получают автоисключения. Ранее сохранённая история не удаляется при смене порога, месяца, перезагрузке или выключении автоисключения.

До порога показан прогресс «Копим данные»; по достижении — доля корзин от выбранной основы и оценка. Все возвращённые WB поисковые кластеры сохраняются, даже если показов меньше 100. Кластер объединяет похожие фразы. CPC имеет views=null; приложение не подменяет показы кликами или нулём, оценка по показам недоступна до явной смены основы на клики. Данные по товару/кампании/магазину разделены.

PostgreSQL: migration 153. Сбор от последних доступных 30 дней с момента включения. Более ранняя отсутствующая история не выдумывается. Непересекающиеся 7-дневные сегменты сохраняются отдельно; повторный ответ заменяет только соответствующий сегмент в одной транзакции, а не добавляет его ещё раз. Итог суммируется по сегментам за всё сохранённое время. Исправления WB обновляют ещё доступные сегменты, вышедшие за 30-дневное окно замораживаются. Пропуски и ошибки загрузки видны; нулевой ответ без группы не стирает предыдущие данные.

Отдельный фоновый цикл. Не более 100 пар кампания/артикул в одном запросе с одинаковым диапазоном дат. Для каждого токена и endpoint в PostgreSQL атомарно резервируется слот 12 минут + запас; 429 может только продлить его. Токены не попадают в UI. Клиентские GET читают только PostgreSQL, без WB.

Ручное/автоматическое исключение проходит через очередь: сначала текущий список минус-фраз WB, затем объединение с новой фразой (до 1000), затем отдельная проверка. Старые исключения не обнуляются. Неизвестная структура списка или неподдерживаемый режим кампании показывают ошибку; успех до read-back не объявляется. Автоисключение требует явно включённой настройки, достигнутого порога, процента ниже минимального, известных нулевых заказов и свежих полных текущих сегментов. Отключение автоматического режима отменяет ещё не отправленные автоматические исключения; ручные команды сохраняются, отправленные проверяются. Перед отправкой автоочередь повторно проверяет порог и заказы. Паузы, ставки, бюджеты и существующая защита остатков не меняются.

Источники: https://dev.wildberries.ru/api/swagger/yaml/ru/08-promotion.yaml?region=ru — получено 30.10.2026. POST /adv/v0/normquery/stats, /get-minus, /set-minus. Применимость исключения к конкретной CPC-кампании подтверждается ответом WB, без обхода ограничений.

При первом открытии сервер сразу планирует только сбор статистики с соблюдением общей очереди и сохранённых слотов WB; команды исключения этот запуск не выполняет. Самые свежие незагруженные сегменты идут первыми. Панель перечитывает сервер каждые 15 секунд, пока открыта и нет несохранённых настроек/активного ввода. Ошибка первой загрузки видна, сохранённые данные остаются. Ручное исключение доступно для существующей строки без порога 100; активность/исключение подтверждается отдельно ответом WB.
